# Contributing to the DIAMOND website

> **Branch protection**
> The `main` branch is protected: direct pushes are blocked and will be rejected. Always create a feature branch for your changes, then open a pull request so the website administrator can review and merge it. This keeps production stable and ensures every update is traceable.

> **Dependency files**
> Files `package.json` and `package-lock.json` contain the locked dependencies for the Node.js environment. They should not be edited or modified. Note that it's possible that by running `npm install` in your local development environment these two files get automatically updated. In that case **DISCARD those modifications before committing**.

It's strongly recommended to (i) make modifications on a local branch derived from `dev`, (ii) start a local server to visually check contributions and make sure the website keeps building (explained below), and then (iii) push the contribution to the GitHub repository creating a pull request onto `dev`.

This way, the website administrator can review and merge contributions, while contributors can preview the modifications locally before pushing them to the repository.

## Local development

To run the site locally in development mode, the following dependencies must be met:

- `Node.js` LTS version. Check it with`node -v`.
- Hugo **extended** latest version (`v0.166.0` at the time of writing). Check it with `hugo version`.

### Install `Node.js`

1. Install _Node Version Manager_ (`nvm`) following [their repository install instructions](https://github.com/nvm-sh/nvm#installing-and-updating).
2. Restart the terminal, and [verify the installation was successful](https://github.com/nvm-sh/nvm#verify-installation).
3. Install the LTS `Node.js` version with `nvm install --lts`.
4. Finally, verify the installation with `node -v` and `npm -v`.

### Install Hugo Extended

The installation process for Hugo is [clearly documented](https://gohugo.io/installation/) for all platforms. However, it's important to install the **extended** version of it, otherwise build time errors might appear.

For example, on Linux, the easiest way to get Hugo up and running is through the [prebuilt binaries](https://gohugo.io/installation/linux/#prebuilt-binaries). 

1. Download the [latest version](https://github.com/gohugoio/hugo/releases/latest) (look for package `hugo_extended_[version]_linux-amd64.tar.gz` **in the assets section**, and adjust for the architecture too).
2. Extract the archive, and move the `hugo` executable to a directory on the `PATH` environment variable (or to any directory and then include it in the `PATH`). Normally `~/.local/bin` is a good place.
3. Verify the installation with `hugo version`.

### Clone and set up the website locally

Clone this GitHub repository

```bash
git clone https://github.com/diamond-diadem/diamond-diadem.github.io.git diamond-website
```

Install the `Node.js` dependencies

```bash
cd diamond-website
npm install
```

And finally access the development server:

```bash
npm run dev
```

This command starts a local development server that builds the website from your current source files and branch. The site will automatically refresh with each edit. By default, you can visit it at `http://localhost:1313`, or any address reported at the end of the standard output.

> After some edits, you may need to stop the server (Ctrl+C) and restart it to see the changes reflected.
> In case of issues, try clearing the Hugo cache with `hugo --gc`.

## Content organization and Markdown tips

The website is generated by Hugo from the `.md` files contained inside the `content` folder on this repository. Directly under `content` are located the main sections of the website, with their sub-sections and pages down the hierarchy.

Let's assume the contributor's work is to create a new code. To that end, the `codes` [archetype](https://gohugo.io/content-management/archetypes/) can be used as follows (note that not all sections might have archetypes)

```bash
hugo new content codes/scientific-computing/lammps/index.en.md
```

Here, Hugo will use the `archetypes/codes.md` archetype to generate an `index.en.md` file, where users can add the LAMMPS code information they want to include on the website.

Note that:
1. This is the English version of the content, for the French version just copy-paste `index.en.md` into `index.fr.md` and adjust the content accordingly.
2. The initial state of the page is as [draft](https://gohugo.io/methods/page/draft/), so it won't be visible until this front-matter property is either removed or explicitly turned to `false`.
3. The `codes/scientific-computing/lammps/index.en.md` structure creates a [Leaf Bundle](https://gohugo.io/content-management/page-bundles/#leaf-bundles), which means that it can hold any other related content of this page like images, documents, etc., alongside the `index.[en|fr].md` files, inside the `lammps` directory. See below how to include images, for example.

### Syntax References

The full reference of tools, tips, and tweaks for this website come from the theme is uses.

- Doks [Basic](https://getdoks.org/docs/reference/markdown-basic-syntax/) guide.
- Doks [Advanced](https://getdoks.org/docs/reference/markdown-extended-syntax/) guide.

Additional and/or most used features are described in the coming sections.

### External links

The syntax to include external links in Markdown is

```markdown
[Link text](URL)
```

### Internal Links

For internal links within the website, include only the part of the URL after the website's main address, **without the language code**, and using Hugo's `ref` method. For example, to link to `https://diamond-diadem.github.io/en/codes/visualisation/paraview/`, use:

```markdown
[ParaView]({{% ref "/codes/visualisation/paraview/" %}})
```

### Opening Links in a New Tab

To open a link in a new tab, use the following HTML syntax, although **this should be avoided** because it breaks the global behavior of the website's links. Use it only when exceptionally needed:

```html
<a href="https://example.com" target="_blank" rel="noopener noreferrer">Example</a>
```

The `target="_blank"` attribute ensures the link opens in a new tab. Always pair it with `rel="noopener noreferrer"` for external links. The `link-card` shortcode adds this `rel` value automatically when used with `target="_blank"`.

### Images

Place the image you want to add (e.g., `image.png`) either in the page bundle, next to the page's `index.[en|fr].md` files, or in the `static/images/` folder. The former is recommended for small images used by a single page, the latter for images shared across pages or large images/files.

To insert the image into the page, it's recommended to use the `figure` [shortcode](https://gohugo.io/content-management/shortcodes/). It can be used by placing something similar to the following in the content's `.md` file where the image must appear:

```markdown
{{< figure src="image.png"
    alt="Graphical description of a workflow."
    caption="Workflow for the ML potential."
    width="text"
    dark="image-dark.png" >}}
```

- `src` is the path to the image being included. If you followed the `leaf bundle` approach encouraged before, then the image will be a sibling of the `.md` file and just its name will suffice.
- `alt` is the alternative text, and **it's required**. Describe what the image shows, so that screen reader users get the same information.
- `caption` is the caption text to be shown below the image.
- `width`'s default value is `text`, which sets the image width to fill the text column. `width`'s value set to `wide` makes the image extend past the text on both sides where there's room.
- `dark` is the path/name of the image's dark-themed version (see next section for more information).

#### Adapting Images for Light/Dark Themes

If an image colors were designed for a light theme, then they might be hard to see in a dark one. In these situations, it's better to have two versions of the same image: one for each theme. To specify this difference, add a dark-mode version of the image next to the original (assuming the original was made for light themes) with the same name plus a `-dark` suffix, and the same extension:

```text
content/documentation/use/my-page/
├── index.en.md
├── index.fr.md
├── diagram.png        # shown in light mode
└── diagram-dark.png   # shown in dark mode
```

Nothing else changes: keep referencing the image once, by its light name, and the matching version is shown automatically when the reader switches themes.

The light version may also be named with a `-light` suffix (`diagram-light.png`), if preferred. This works the same for images in `static/images/`. Only the version being displayed is downloaded.

### Quarantining Likely-Unused Static Files

When an asset in `static/` looks unused, move it to the matching path under `static.old/` first instead of deleting it immediately. This keeps the build clean while preserving a safe review period before the files are removed from the project.

## Codes section

### Add a new code page

Each code is a folder (a Hugo _page bundle_) under `content/codes/<category>/`. The folder **is the code's slug** (lowercase, hyphens: `amitex-fftp`) and holds both language pages together with the code's images:

```text
content/codes/scientific-computing/abinit/
├── index.en.md
├── index.fr.md
├── logo.svg        # page header (see below)
├── logo-dark.svg   # optional: replaces the logo in dark mode
├── icon.svg        # small square mark for menus and catalogs
└── icon-dark.svg   # optional: replaces the icon in dark mode
```

`<category>` is the **type** of the code: `scientific-computing` (simulation and computing codes) or `visualisation`. Nothing else wires the code in: the Codes landing page (`codes-catalog` shortcode), the menus and the home page pick it up from these files.

#### 1. Create the pages

```bash
hugo new content codes/<category>/<slug>/index.en.md
```

The `codes` archetype fills in the front matter and the usual page structure. Copy `index.en.md` to `index.fr.md` and translate it. **Always change both languages together.**

#### 2. Fill in the front matter

| Key           | What to put                                                                                                                                |
|---------------|--------------------------------------------------------------------------------------------------------------------------------------------|
| `title`       | The code's name.                                                                                                                           |
| `description` | One sentence for search engines and link previews, **110–160 characters** (the build warns otherwise).                                     |
| `tagline`     | A few words shown under the name in the catalog card, such as "Plane-wave DFT suite". Set it in both languages.                            |
| `scale`       | The catalog group: `electronic`, `atomic`, `mesoscopic`, `microstructure` or `macroscopic`. Not translated. Ask the maintainers if unsure. |
| `website`     | The code's official website, linked from the page header.                                                                                  |
| `weight`      | Position in the menu (usually the highest weight in the category, plus one).                                                               |
| `draft`       | The archetype sets `true`: remove it when the page is ready to be published.                                                               |

The archetype's `toc: true` shows the contents sidebar (it is hidden automatically on pages without headings); set `toc: false` only for a specific reason. Do not add `title_visible` or `icon`: the title comes from the logo/header and the icon from the `icon.<ext>` file.

#### 3. Add the logo and the icon

A code has two images, each used in different places:

- **Logo** (`logo.<ext>`, optional `logo-dark.<ext>`): the large branding image at the top of the code's own page. It may be wide, with a wordmark or tagline.
- **Icon** (`icon.<ext>`, optional `icon-dark.<ext>`): a small **square** mark for the places where space is tight: the menus, the Codes catalog cards, and the tutorials of this code (through their `code:` front matter). A wide logo would be unreadable there, so the icon is a compact version of it, such as the initial or the symbol.

Both are found **by file name**: no CSS and no front matter. Accepted formats are SVG (preferred: sharp at any size), PNG, JPG and WebP; icons are converted to WebP automatically. Add the `-dark` version when the image is unreadable on a dark background (a black mark, for example).

If the code has no official logo, the icon alone is enough (see `n2p2`): the page header then shows the `title` as large text. If it has no icon either, a letter in a bold sans-serif font makes a fine placeholder, and the build warns about a code without an icon.

#### 4. Write the content

Follow the structure of the archetype and of the existing code pages:

1. `### Retrieve the container image` (FR `### Récupérez l'image de conteneur`) with Apptainer/Docker `tabs`.
2. One or more paragraphs describing what the code does and what it is used for.
3. `## Tutorial` (FR `## Tutoriel`), `## <Code> documentation` (FR `## Documentation <Code>`) and `## Examples` (FR `## Exemples`), each with `link-card`s. Items that do not exist yet stay as disabled cards (`title="Content to be added"`, `href="#bottom"`, `disabled="true"`).

If the code has a tutorial, create it in `content/documentation/by-container/` with `code: <slug>` in its front matter so it shows the code's icon.

#### The page header

Every code page gets the same header, built by `layouts/_partials/main/code-header.html`:

- The logo is the page's main heading, and the code's `title` is its text alternative for screen readers. **Without a logo file, the `title` is shown in its place** as large text, so a page always has a heading.
- When `website` is set, a round arrow button at the top-right corner of the logo links to it, in a new tab.
- The last-update date and the link to the other language follow below.

#### Checklist before opening a PR

- [ ] `index.en.md` and `index.fr.md` both exist and say the same.
- [ ] `description` is 110–160 characters in both languages; `tagline` and `scale` are set.
- [ ] `icon.<ext>` exists (plus `-dark` variants where needed) and `logo.<ext>` if the code has one.
- [ ] `draft: true` is removed.
- [ ] A local build (`npm run dev`) shows the code in the catalog, with no warnings in the terminal, in light and dark mode.

### Math Support

The website supports `$...$` delimiters for LaTeX syntax in inline math. For block equations, use the following format:

```markdown
$$
(...)
$$
```

Math rendering is loaded only on pages that declare `math: true` in front matter. Add that flag when introducing a page with LaTeX content.

## News section

Create a news post with `hugo new content news/<slug>/index.en.md` (the `news` archetype), copy it to `index.fr.md` and translate it. Drop the card picture next to them as `card.<ext>`.

| Key               | Meaning                                                                                                   |
| ----------------- | --------------------------------------------------------------------------------------------------------- |
| `title`           | Headline of the post.                                                                                     |
| `description`     | 110–160 characters; also the SEO text, so there is no `seo:` block.                                       |
| `summary`         | Plain text shown on the card; ` · ` becomes a line break.                                                 |
| `eventDate`       | Free text, such as `November 24 to 26, 2025`.                                                             |
| `cardImage` | The card picture: a file in the post's folder, or a shared `images/...` asset.                            |
| `weight`          | Card order, lowest first.                                                                                 |
| `draft`           | The archetype sets `true`: remove it to publish.                                                          |
| `toc`             | Keep `false`: news pages have no contents sidebar.                                                        |

Do not add `tags`, `categories`, `contributors`, `pinned`, `homepage` or `backgroundOpacity`: nothing reads them.

## YouTube Video Integration (Tutorials)

To integrate a YouTube video, use the custom Diamond shortcode:

```markdown
{{< video-with-consent id="{video-id}" >}}
```

Replace `{video-id}` with the YouTube video ID. To obtain this ID, go to the YouTube video page, click the "Share" button, and copy the link of the form `https://youtu.be/{video-id}`.

### Features of the Shortcode

- Maintains a fixed aspect ratio (48:27) with 100% width for optimal adaptability.
- Enables privacy-enhanced mode via `youtube-no-cookie.com`.
- Integrates cookie consent management (if configured in `config/`).
- Automatically adapts subtitles to match the page language.

## Adding FAQs to the Home page

FAQs live inside `content/faqs/`, and they are simple `.md` files with the following form:

```md
---
title: "Frequent question?"
weight: 100
---

Answer to this question.

Can even take multiple lines, and probably use links, math equations, etc.
```

To add FAQs, create a new file with this structure inside the mentioned folder, and it should be it. For example, `content/faqs/why-guix.[en|fr].md`, where choosing `en` or `fr` will determine which language it's being targeted.

Some times restarting the server is required to get the modifications up and running.
